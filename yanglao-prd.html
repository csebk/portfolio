一、文档概述

1.1 产品定位

养老AI助手是一个基于RAG技术的智能问答工具，为养老从业者（保险代理人、护理人员、社区工作者）提供准确的养老政策、产品信息和专业知识查询服务。

1.2 目标用户

用户群 角色 核心痛点
保险代理人 日常向客户解答养老政策/产品问题 政策文件多且更新快，记不住；客户问得细，回答不准
养老机构员工 需要快速了解长护险、补贴政策 培训成本高，新人上手慢
社区养老工作者 回答居民关于养老服务的咨询 缺乏统一知识来源，回答口径不一致

1.3 核心价值主张

维度 价值
对从业者 "秒查政策、准确回答、统一口径" — 降低知识获取成本
对客户 "专业可信、回答一致" — 提升信任感和成交率
对机构 "降低培训成本、提高服务质量" — 标准化知识输出

1.4 与银发管家的关系

维度 银发管家（C端） 养老AI助手（B端）
目标用户 老人 + 子女 养老从业者（代理人/护理人员）
核心功能 用药提醒 + 健康管理 + 情感陪伴 政策问答 + 产品知识 + 话术辅助
技术重点 语音交互 + 主动关怀 + RAG RAG深度优化 + 知识库管理
商业模式 C端订阅 + B端增值服务 B端SaaS订阅
协同关系 养老AI助手为银发管家提供后端知识支持 银发管家为养老AI助手提供C端验证场景

二、功能需求

2.1 功能全景与优先级

养老AI助手 V1.0（MVP）
├── P0-核心功能（必须上线）
│   ├── F1: 政策问答（长护险+补贴政策）
│   └── F2: 产品知识问答（泰康之家等）
├── P1-重要功能（V1.1上线）
│   ├── F3: 销售话术辅助
│   └── F4: 知识库管理后台
└── P2-锦上添花（V2.0规划）
    ├── F5: 方言语音交互
    └── F6: 多模态（图片识别政策文件）

2.2 功能详细需求

F1：政策问答（P0）

用户故事：

作为一位保险代理人，当我被客户问到"上海长护险怎么申请"时，我希望AI能立即给出准确的政策解读，这样我就不用翻找文件、也不会答错。

功能描述：
- 代理人用自然语言提问养老政策相关问题
- AI基于RAG知识库检索最新政策文件后回答
- 回答附带来源文件和日期，确保可追溯
- 支持多地区政策对比查询

业务规则：
| 规则编号 | 规则描述 | 触发条件 | 执行动作 |
|----------|----------|----------|----------|
| BR-01 | 政策检索 | 代理人提问政策相关问题 | RAG检索相关政策文件Top-3 |
| BR-02 | 答案生成 | 检索到相关文档 | LLM基于文档生成结构化回答 |
| BR-03 | 引用标注 | 回答生成后 | 自动附加来源文件名称和更新日期 |
| BR-04 | 未找到答案 | 检索相似度<0.6 | 回答"暂未查到相关政策，建议咨询当地社保局" |
| BR-05 | 政策更新提醒 | 知识库有新政策文件 | 主动推送"XX地区长护险政策已更新" |

AI能力需求：
- RAG检索增强生成（向量数据库 + 大模型）
- 政策文件智能解析（PDF/Word → 结构化文本）
- 多地区政策对比（自动提取关键差异点）

数据字段：

{
  "query": "上海长护险申请条件",
  "retrieved_docs": [
    {
      "doc_id": "policy-shanghai-lchi-2026",

      "updated_at": "2026-06-15",
      "relevance_score": 0.92,
      "key_points": ["年满60周岁", "失能评估3-6级", "医保参保"]
    }
  ],
  "answer": "上海长护险申请条件如下：1. 已参加本市基本医疗保险...（详见《上海市长期护理保险实施细则》2026年6月修订版）"
}

F2：产品知识问答（P0）

用户故事：

作为一位保险代理人，当我需要向客户介绍泰康之家的园区时，我希望AI能快速给出各园区的对比信息，这样我可以更高效地为客户提供专业建议。

功能描述：
- 代理人查询养老社区、保险产品等信息
- AI基于产品知识库回答，支持对比查询
- 自动提取关键差异点（价格、位置、设施等）
- 支持生成对比表格

业务规则：
| 规则编号 | 规则描述 | 触发条件 | 执行动作 |
|----------|----------|----------|----------|
| BR-01 | 产品检索 | 代理人提问产品信息 | RAG检索产品文档Top-3 |
| BR-02 | 对比生成 | 查询多个产品 | 自动生成对比表格 |
| BR-03 | 卖点提炼 | 代理人请求"推荐话术" | 基于产品特点生成销售话术 |
| BR-04 | 价格更新 | 产品价格/政策变更 | 自动更新知识库并通知代理人 |

F3：销售话术辅助（P1）

用户故事：

作为一位保险代理人，当客户提出价格异议时，我希望AI能给我提供应对话术，这样我可以更有信心地与客户沟通。

功能描述：
- 代理人输入客户异议场景（如"太贵了""再看看"）
- AI基于历史成交案例和金牌代理人话术库生成应对建议
- 提供多角度回应策略（拆分成本法、对比法、保险衔接法）
- 标注注意事项（避免使用的词汇、需要补充的信息）

AI能力需求：
- 场景分类（识别客户异议类型）
- 话术生成（基于案例库的个性化生成）
- 安全护栏（标注不当话术风险）

F4：知识库管理后台（P1）

用户故事：

作为养老AI助手的管理员，我希望能够方便地上传和更新政策文件、产品信息，这样AI的回答就能始终保持最新。

功能描述：
- 管理员上传政策文件（PDF/Word/图片）
- 系统自动解析、分割、向量化、入库
- 支持手动编辑知识库片段
- 知识库更新日志和版本管理
- 问答数据统计（热门问题、未命中问题）

业务规则：
| 规则编号 | 规则描述 | 触发条件 | 执行动作 |
|----------|----------|----------|----------|
| BR-01 | 文件上传 | 管理员上传PDF/Word | 自动文本提取+分割+向量化 |
| BR-02 | 知识审核 | 新文件入库后 | 标记为"待审核"，管理员确认后生效 |
| BR-03 | 版本管理 | 政策文件更新 | 保留旧版本，标记变更点 |
| BR-04 | 数据统计 | 每日定时 | 生成热门问题排行、未命中问题清单 |

3.2 知识库构建流程

原始文档（PDF/Word/网页）
    ↓
文本提取（PyMuPDF/docling）
    ↓
文本清洗（去除页眉页脚、特殊符号）
    ↓
智能分割（按主题/章节，每段500-800字）
    ↓
向量化（text-embedding-3-small → 1536维）
    ↓
存入pgvector（带metadata：来源、日期、地区）
    ↓
定期更新（政策文件变更时重新索引）

四、AI模型选型与RAG设计

4.1 模型选型

用途 模型 理由 成本估算
政策问答 通义千问Qwen-Max 中文理解强，适合政策解读 ~¥0.04/千token
产品问答 通义千问Qwen-Turbo 成本低，速度快 ~¥0.001/千token
话术生成 通义千问Qwen-Plus 平衡成本与质量 ~¥0.008/千token
向量检索 text-embedding-3-small 中文效果好，成本低 ~¥0.0001/千token

4.2 RAG检索策略

混合检索：

用户提问 → 问题向量化 → 向量检索(Top-10) → BM25关键词检索(Top-10) → 融合排序 → Top-3 → 拼接Prompt → Qwen生成

检索参数：
| 参数 | 值 | 说明 |
|------|------|------|
| Top-K（初筛） | 10 | 向量+关键词各取Top-10 |
| 相似度阈值 | 0.7 | 低于此值标记为"未找到" |
| 文档最大字数 | 2000字 | 超过则截断或摘要 |
| 重排序模型 | bge-reranker-large | 提高Top-K精度 |
