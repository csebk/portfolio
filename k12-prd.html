第一部分 · 产品定义（承接 v0.2，已收敛）

1. 背景与问题定义

背景：公司在 K12 学校教育方向做 0→1 孵化（同期探索医疗/影视 AIGC/法律，本产品聚焦教育线）。硬件不自研，与钉钉合作，用其课堂录音卡片设备采集课堂数据，直接嵌入学校教学流程。

核心问题：
- 学生：课堂信息转瞬即逝，记笔记=漏听讲；课后不知道预习/复习什么。
- 教师：面对几十个学生无法即时感知教学效果，反馈滞后。
- 共性：班级授课制下因材施教难落地。

产品目标（一句话）：以课堂录音为数据源，用 AI 降低师生信息处理成本，把"培养良好学习习惯"落成可执行、可量化的日常动作。

2. 定位 / 用户 / 价值（摘要）

  • 定位：嵌入 K12 学校教学流程的 AI 教学助手，B端切入（学校/老师），服务 C端（学生/家长）。Demo 聚焦初中数学。
  • 差异化定位（市场校准后）：市场已被割裂的单点产品占据——希沃只做教师反馈（重硬件/校端教研）、松鼠/作业帮只做学生分层（不碰课堂）、钉钉A1/通义听悟只做通用录音摘要（不做学科/反馈/分层）。本产品是唯一把"同一段课堂录音"同时转成①学生分层笔记②教师循证反馈③家长通知的"一鱼三吃"轻量工具，且死磕初中数学垂直（公式/步骤/知识点热词）+ 老师0操作0硬件改造。详见 §18。
  • 核心用户：初中数学老师（主）、初中学生（核心）、家长（外围·纯通知）、学校管理者（决策）。
  • 价值：老师 0 操作拿反馈；学生专心听、课后拿笔记+分层预复习；学校沉淀教学数据资产。

3. 范围与优先级（MoSCoW · v1.1 市场校准）

v1.1 调整说明：①Demo 主线收窄——"数学步骤化学生笔记"为唯一必须打穿的深水区（通用工具做不出、纯音频可交付）；教师反馈与分层做轻量演示版，避免三头都浅。②教师反馈剔除视觉类指标（纯音频采不到抬头率/微笑），仅承诺音频可靠产出的维度。③分层"知识点级"明确为 v2 目标，Demo 用成绩标签冷启动的 basic/advanced 仅供老师参考。

第二部分 · 功能规格详述（FSD）

约定：每个功能给出【触发】【输入】【处理规则】【输出】【边界/异常与降级】。字段命名同 §6 数据模型。

5. 系统主链路

钉钉录音卡片采集音频
  → [F1] 音频上传与课堂建档
  → [F2] ASR 转写
  → [F3] 结构化理解(分环节/识别数学知识点/捕捉互动)
      ├→ [F4] 学生课堂笔记生成
      ├→ [F5] 教师上课反馈生成
      └→ [F6] 分层预习/复习生成
  → [F7] 教师端查看与分发
  → [F8] 家长纯通知

F1 音频上传与课堂建档

  • 触发：一节课结束，录音卡片音频经钉钉侧回传；或教师端手动上传（demo 兜底）。
  • 输入：audio_file(音频)、class_id、teacher_id、subject=math、start_time、duration、topic(可选，课题)。
  • 处理规则：
  • 校验音频格式(mp3/wav/m4a)、时长(≥5 分钟才处理，<5 分钟标记 too_short)。
  • 创建 ClassSession 记录，状态置 uploaded。
  • 触发异步转写任务。
  • 输出：session_id + 状态 uploaded。
  • 边界/异常：格式不支持→拒绝并提示；时长过短→too_short 不生成内容；上传失败→可重试 3 次。

F2 ASR 转写

  • 触发：F1 建档成功后异步调用。
  • 输入：session_id + 音频。
  • 处理规则：
  • 调 ASR 服务，输出带时间戳与说话人分离(teacher/student)的转写文本。
  • 应用数学学科词库纠错（如"移项/因式分解/一元一次方程"）。
  • 写入 Transcript，状态 transcribed；失败置 transcribe_failed。
  • 输出：transcript_id + 分段文本(含 timestamp、speaker、text)。
  • 边界/异常：识别置信度低于阈值的段落标 low_confidence=true（供人工校准/前端弱化展示）；ASR 超时/失败→重试 2 次仍失败置 transcribe_failed，通知运营。

F3 结构化理解

  • 触发：F2 成功后。
  • 输入：transcript_id 分段文本。
  • 处理规则（LLM）：
  • 切分课堂环节（导入/新授/例题讲解/练习/小结）。
  • 抽取本堂数学知识点列表（含公式/定理/解题方法）。
  • 识别师生互动（提问/回答/讨论）及疑似难点（学生反应弱/反复讲解的环节）。
  • 输出：StructuredContent（环节数组、知识点数组、互动数组、难点数组）。
  • 边界/异常：转写质量差导致无法抽取→降级为"仅时间轴笔记"，并标 degraded=true。

F4 学生课堂笔记生成

  • 触发：F3 成功后。
  • 输入：StructuredContent + subject=math。
  • 处理规则：按数学笔记模板生成（见 §11 AI 规格）；重点/难点标注；例题解法步骤化；公式规范排版(LaTeX/图片)。
  • 输出：Note（markdown 结构化正文 + 知识点标签 + 重点/难点 flag）。
  • 边界/异常：内容为空→不生成，标 no_content；生成超时→重试1次。

F5 教师上课反馈生成（v1.1 循证参考定位）

  • 触发：F3 成功后（与 F4 并行）。
  • 输入：StructuredContent + Transcript（含时间戳，用于溯源）。
  • 定位（v1.1 关键校准）：反馈为"提示/参考"而非"评价/打分"——命中政策红线"严禁直接用 AI 输出作为评价结论"，也规避行业公认痛点（AI 判题不准→老师不信）。每份报告保留教师修正/采纳/忽略入口。
  • 处理规则：生成以下维度反馈——
  • ①知识点覆盖度（planned/covered/missed）
  • ②课堂时间分配（讲授 / 互动 / 练习 时长占比，基于转写时间戳测算，可视化时间轴）
  • ③师生互动·提问有效性（提问频次、开放性提问占比、候答时间、追问深度，替代原粗粒度"互动"）
  • ④疑似难点（含 evidence）
  • ⑤可执行改进建议（恰好 3 条，指向具体知识点）
  • 溯源（v1.1 新增·最重要）：每条结论/难点/建议须附 evidence_refs——可跳转回对应转写片段与音频时间戳（对标希沃"证据链"卖点；无溯源老师不信）。
  • 输出：FeedbackReport（结构化维度 + 建议数组 + 每项 evidence_refs）。
  • 能力边界（v1.1 诚实声明）：纯音频不采集视觉信号（抬头率/微笑/表情），故不产出任何视觉类指标；嘈杂/多人同时说话的片段，互动与节奏识别置信度下降，低置信结论标 low_confidence 并弱化展示。
  • 约束：不增加老师任何录入；建议必须可执行、具体到知识点；结论以参考语气呈现，禁"给老师打分定性"。

F6 分层预习/复习生成

  • 触发：F4 完成后，按班级学生名单逐人生成。
  • 输入：Note + 每个学生的 level(basic/advanced)。
  • 分层规则（双来源）：
  • 冷启动：读学校提供的数学成绩标签 → basic / advanced。
  • 建档细化：随使用回流(笔记完成度、复习正确率、错题分布)更新 StudentProfile，动态修正 level。
  • 无成绩标签的学生→默认 basic，并标 level_source=default。
  • 输出：每生一份 LearningTask（预习提纲 + 复习任务，按档差异化难度/题量）。
  • 可见性与伦理约束（v1.1 新增）：分层层级（basic/advanced）仅对老师可见，作教学参考；家长端纯通知绝不透露层级，学生端也不显式标注"你被分到 basic"——规避"给学生贴标签/教育公平"敏感线（对标松鼠/作业帮均避免用单一总分给学生贴层）。
  • 失真风险与演进（v1.1 新增）：Demo 用学校成绩标签（总分）冷启动，须明确其局限——总分掩盖具体知识点漏洞；分层维度尽快从总分升级到知识点级（v2 目标，结合 weak_points 回流），避免静态标签失真。
  • 边界/异常：学生名单缺失→仅生成班级通用版；某生 profile 缺失→走 default。

F7 教师端查看与分发（钉钉内）

  • 触发：F5 完成，教师打开钉钉工作台入口。
  • 功能：课堂列表→反馈报告详情→一键分发(笔记给学生/通知给家长)。
  • 边界/异常：内容生成中→展示"处理中"状态；分发失败→可重试并提示。

F8 家长纯通知

  • 触发：教师分发 或 系统定时(课后 + 复习提醒时间点)。
  • 功能：推送今日数学课堂摘要 + 复习提醒（纯展示，无交互）。
  • 边界/异常：家长未绑定→跳过并记录 parent_unbound。

第三部分 · 数据与接口

6. 数据模型（核心实体）

Demo 级，字段可扩展。类型示意：str/int/enum/datetime/json/text。

School：school_id(PK), name
Class：class_id(PK), school_id(FK), name(如"初二3班"), grade
Teacher：teacher_id(PK), school_id, name, dingtalk_userid, subject
Student：student_id(PK), class_id, name, dingtalk_userid(可空)
Parent：parent_id(PK), student_id(FK), dingtalk_userid(可空), bound(bool)
ClassSession（课堂）：session_id(PK), class_id, teacher_id, subject, topic, start_time, duration, status(enum: uploaded/transcribed/structured/generated/failed/too_short), created_at
Transcript：transcript_id(PK), session_id(FK), segments(json: [{start,end,speaker,text,low_confidence}]), status
StructuredContent：struct_id(PK), session_id, phases(json), knowledge_points(json), interactions(json), difficulties(json), degraded(bool)
Note（学生笔记）：note_id(PK), session_id, content_md(text), knowledge_tags(json), highlights(json), status
FeedbackReport（教师反馈）：report_id(PK), session_id, coverage(json), time_distribution(json: {lecture_pct,interaction_pct,practice_pct}), interaction_analysis(json: {total_questions,open_ended_pct,avg_wait_sec,follow_up_depth}), difficulties(json: [{point,evidence,evidence_refs}]), suggestions(json: 3条,每条含 evidence_refs), low_confidence(bool), teacher_action(json: 每项的 采纳/忽略/修正), status
StudentProfile（学生画像/建档）：student_id(PK), level(enum: basic/advanced), level_source(enum: school_score/system_built/default), note_completion_rate(float), review_accuracy(float), weak_points(json), updated_at
LearningTask（分层任务）：task_id(PK), student_id, session_id, type(enum: preview/review), level, content_md(text), item_count(int), completed(bool)
Notification（家长通知）：notif_id(PK), parent_id, session_id, type(enum: summary/reminder), content(text), sent_at, status(enum: sent/failed/skipped)

关系（ER 摘要）：School 1-N Class 1-N Student 1-1 StudentProfile；Student 1-N Parent；Class 1-N ClassSession 1-1 Transcript 1-1 StructuredContent；ClassSession 1-1 Note、1-1 FeedbackReport、1-N LearningTask；Parent 1-N Notification。

7. 接口契约（API · demo 级示例）

统一：REST/JSON，Content-Type: application/json；鉴权 Header Authorization: Bearer <token>；统一错误体 {"code":int,"msg":str,"data":null}。错误码：0成功 / 40001参数错 / 40101未授权 / 42201音频不合规 / 42202时长过短 / 50001转写失败 / 50002生成失败 / 50000系统错。

外部对接（demo 级说明）

  • 钉钉：①教师端载体——通过钉钉工作台 H5/微应用嵌入，用钉钉免登获取 dingtalk_userid 映射 teacher_id；②录音卡片取数——从钉钉侧回调/拉取课堂音频(接口以钉钉开放平台文档为准，demo 可用手动上传兜底)；③家长通知——经钉钉消息/工作通知下发。
  • ASR 服务：POST {asr_endpoint}/transcribe，入参音频URL+hotwords=数学词库，异步回调本系统 /api/v1/asr/callback。热词库开放校本自定义（v1.1）：支持学校/老师按教材版本、常用口头表述导入自定义热词（对标讯飞听见/通义听悟；B端落地刚需）——hotwords = 系统数学基础词库 ∪ 校本自定义词库。
  • LLM 服务：内容生成统一走内部生成服务封装(prompt 见 §11)，入参 StructuredContent，出参对应结构化 JSON；需设置超时与重试。

9. 非功能需求（可测量）

  • ⚠️ 合规：Demo 阶段搁置真实学生录音；正式进校前必须补齐(PIPL/未成年人保护/双重知情同意/数据最小化/可删除)。
  • 音频能力边界（v1.1 明确）：本产品仅采集课堂音频（无视觉多模态硬件），不承诺任何视觉类指标（抬头率/微笑/表情/坐姿）；教师反馈仅覆盖音频可靠推断的维度（覆盖度/时间分配/提问有效性/难点）。嘈杂或多人同时说话场景转写与互动识别准确度会下降，低置信内容显式标注，不做过度承诺。
  • 性能：单堂课全链路(上传→笔记+反馈就绪) ≤30 分钟；转写字准率(课堂中文+数学术语) ≥90%；教师端页面首屏 ≤2s。
  • 并发：demo 支持同校 ≥20 节课并行处理排队不丢。
  • 兼容：钉钉最新版 iOS/Android + 钉钉工作台 H5；学生/家长端主流手机浏览器。
  • 可用性：老师端 0 学习成本、0 额外录入。
  • 可靠性：转写/生成失败有重试与状态可见，不静默丢任务。

11. AI 内容生成规格（核心）

每类内容给：输出结构 + prompt 设计要点 + 质量约束 + 幻觉兜底。所有生成仅基于本堂转写与结构化内容，禁止编造未出现的知识点。

11.1 学生笔记(F4)
- 输出结构：# 课题 → ## 知识点(定义/公式/定理) → ## 例题与解法(步骤化) → ## 重点难点(标注) → ## 课后待办。
- Prompt 要点：角色="初中数学笔记助教"；输入=结构化知识点+环节+转写；要求=忠实转写、步骤清晰、公式用 LaTeX、面向初中生语言。
- 质量约束：知识点必须来自 knowledge_points；例题引用老师原话/板书。
- 幻觉兜底：无依据不写；转写缺失段落标"(此处录音不清)"。

11.2 教师反馈(F5) — v1.1 循证参考定位
- 输出结构：覆盖度(planned/covered/missed) / 时间分配(讲授/互动/练习占比) / 互动分析(提问频次/开放性占比/候答时间/追问深度) / 难点(含 evidence + 可溯源音频时间戳) / 建议(恰好3条,可执行,指向具体知识点,每条含 evidence_refs)。
- Prompt 要点：角色="资深教研员"；客观、基于证据(引用互动与重复讲解次数)；建议具体化；语气为"参考/提示"而非"评价/打分"；禁"本节课堂整体表现..."类定性表述。
- 质量约束：难点必须给 evidence + 时间戳；建议不空泛(禁"多互动"这类)；所有结论必须附溯源引用。
- 能力边界：纯音频不产出视觉类指标；低置信片段标 low_confidence 弱化展示。

11.3 分层任务(F6)
- 输出结构：预习提纲 + 复习任务(题目/题量按 level 差异)。
- Prompt 要点：输入=笔记知识点+student level+weak_points；basic 侧重巩固基础与本堂难点，advanced 侧重拓展/应用/多步。
- 质量约束：题目围绕本堂知识点；basic 题量适中、难度贴合；advanced 增设应用题。
- 幻觉兜底：不超纲；无 profile 走 basic 默认模板。

11.4 家长通知(F8)
- 输出结构：一句话课堂摘要 + 今日复习提醒(要点+时间)。
- 约束：≤150 字、纯文本、无术语堆砌、家长易懂。

第五部分 · 验收与测试

12. 验收标准（Given-When-Then）

F1 上传建档
- Given 合规音频≥5min，When 上传，Then 创建 session 且 status=uploaded，返回 session_id。
- Given 音频<5min，When 上传，Then status=too_short 且不触发后续生成。
- Given 不支持格式，When 上传，Then 返回 42201 拒绝。

F2 转写
- Given session=uploaded，When 转写完成，Then 生成带时间戳+说话人分离的 segments，status=transcribed。
- Given ASR 连续失败，When 重试耗尽，Then status=transcribe_failed 且告警。

F3 结构化
- Given 转写正常，When 结构化，Then 输出环节/知识点/互动/难点四类且非空。
- Given 转写质量差，When 结构化，Then degraded=true 且降级为时间轴笔记。

F4 笔记
- Given 结构化成功，When 生成，Then 笔记含知识点/例题/重点难点，且知识点均来自 knowledge_points(无编造)。

F5 反馈
- Given 结构化成功，When 生成，Then 反馈含 5 维且建议恰为 3 条、均可执行、指向具体知识点。

F6 分层
- Given 学生有成绩标签，When 生成，Then 按 basic/advanced 产出差异化任务。
- Given 学生无标签，When 生成，Then level=basic 且 level_source=default。

F7 分发
- Given 报告已生成，When 一键分发，Then 笔记送达学生、通知送达已绑定家长，返回各计数，未绑定家长计入 parent_unbound。

F8 家长通知
- Given 家长已绑定，When 分发/定时触发，Then 收到 ≤150 字摘要+提醒。
- Given 家长未绑定，When 触发，Then status=skipped 不报错。

15. Demo 演示脚本（5 分钟 · 初中数学）

  1. 场景引入(30s)：初中数学课"一元一次方程"，老师戴录音卡片正常上课。

18.3 差异化空间

  1. "一段录音，三方产出"的组合是空白——希沃只给老师、松鼠/作业帮只给学生、钉钉A1只给通用摘要。本产品是唯一的一鱼三吃。
  2. 初中数学垂直，竞品多走通用/语文——希沃案例多为小学语文；通用工具不做学科。本产品的数学热词库+LaTeX公式+例题步骤化是通用工具做不出的深的切口。
  3. 老师0操作0硬件改造——希沃需专用AI硬件、讯飞需整套智慧课堂。本产品一张钉钉录音卡+纯软件，实施门槛最低。
  4. 分层冷启动更轻——松鼠靠前置测评、作业帮靠海量做题数据。本产品用学校现成成绩标签冷启动，当天即可用。
