一、文档概述

1.1 产品定位

银发管家是一个面向60+老人及其子女的AI健康管家小程序，用方言语音交互和主动式关怀，帮助老人管好日常健康，让子女安心在外工作。

1.2 目标用户

用户群 角色 核心诉求
老人（60-85岁） 使用者 操作简单、语音交互、健康提醒、情感陪伴
子女（30-55岁） 付费决策者 远程了解父母状态、异常预警、留言互动
泰康代理人 获客渠道 工具赋能客户管理、保险/养老社区转化

1.3 核心价值主张

维度 价值
对老人 "不用学、随时在、有人聊" — 零学习成本的AI健康管家
对子女 "看得见、管得到、放得下心" — 远程照护的数字化桥梁
对代理人 "有工具、有信任、有转化" — 从保险销售到健康管理的延伸

1.4 竞品对标

产品 优势 劣势 银发管家差异化
ElliQ（美国） 主动式陪伴、关系编排引擎 国内不可用、无中文方言 本土化大模型+方言适配+中国文化语境
海尔智慧康养 硬件生态完整、B端落地多 AI深度不足、场景碎片化 软件定义硬件、轻量SaaS方案
优必选智慧康养 机器人产品线全、B端经验足 C端接受度低、硬件成本高 纯软件方案、零硬件门槛
平安好医生 医疗资源丰富 偏医疗、非养老场景 专注养老、主动关怀而非被动问诊

2.2 功能详细需求

F1：智能用药管家（P0）

用户故事：

作为一位患有高血压的老人，我希望每天有人提醒我按时吃药，这样我就不会忘记服药，避免健康风险。

功能描述：
- 老人通过语音/文字设置用药计划（药品名称、剂量、频次、时间）
- AI在设定时间主动推送用药提醒（微信服务通知）
- 老人回复"吃了"或"没吃"，AI自动记录服药状态
- 漏服时：第一次提醒老人，第二次通知子女

业务规则：
| 规则编号 | 规则描述 | 触发条件 | 执行动作 |
|----------|----------|----------|----------|
| BR-01 | 用药提醒 | 到达设定时间 | 推送微信服务通知 |
| BR-02 | 服药确认 | 老人回复"吃了" | 记录✅，生成日报 |
| BR-03 | 漏服处理 | 到达时间后2小时未确认 | 二次提醒 |
| BR-04 | 持续漏服 | 连续2次未服药 | 通知子女："张奶奶今天的降压药还没吃" |
| BR-05 | 药物冲突检测 | 添加新药时 | AI检测药物相互作用风险，提示"此药与您正在服用的XX药可能有冲突，建议咨询医生" |

AI能力需求：
- 药物知识库RAG检索（药品说明书、相互作用数据）
- 用药依从性分析（连续服药记录生成趋势报告）

数据字段：

{
  "medication_id": "uuid",
  "user_id": "老人用户ID",
  "drug_name": "药品名称",
  "dosage": "剂量（如：5mg）",
  "frequency": "频次（如：每日1次）",
  "scheduled_time": "计划时间",
  "status": "pending/confirmed/missed",
  "confirmed_at": "确认时间",
  "reminder_count": "提醒次数"
}

F2：慢病数据管家（手动录入版）（P0）

用户故事：

作为一位糖尿病患者，我希望每天记录我的血糖值，这样AI可以帮我分析趋势，在异常时给我建议。

功能描述：
- 老人通过语音/文字录入血压、血糖、心率等数据
- AI自动记录并生成趋势图（周/月视图）
- AI分析趋势，给出温和建议（非诊断性质）
- 异常值触发分级预警

业务规则：
| 规则编号 | 规则描述 | 阈值 | 执行动作 |
|----------|----------|------|----------|
| BR-01 | 正常范围 | 血压<140/90，空腹血糖<7.0mmol/L | 绿色标记 |
| BR-02 | 注意范围 | 血压140-160/90-100，空腹血糖7.0-10.0 | 黄色标记 + 温和提醒 |
| BR-03 | 警告范围 | 血压160-180/100-110，空腹血糖10.0-14.0 | 橙色标记 + 就医建议 |
| BR-04 | 紧急范围 | 血压>180/110，空腹血糖>14.0 | 红色标记 + 紧急通知子女 |
| BR-05 | 连续异常 | 连续3天同一指标偏高 | 生成周报 + 建议复诊 |

AI能力需求：
- 时序数据趋势分析（移动平均、波动检测）
- 自然语言生成健康建议（基于规则引擎+LLM润色）

数据字段：

{
  "record_id": "uuid",
  "user_id": "老人用户ID",
  "metric_type": "blood_pressure/blood_sugar/heart_rate",
  "value": "测量值",
  "unit": "单位",
  "recorded_at": "记录时间",
  "entry_method": "voice/text/manual",
  "ai_analysis": "AI分析结果",
  "alert_level": "green/yellow/orange/red"
}

F3：子女端远程监控（P0）

用户故事：

作为一位在外地工作的子女，我希望随时能看到父母的健康状况，异常时第一时间收到通知，这样我能放心工作。

功能描述：

- 留言功能：子女给父母留语音，AI在合适时机播放
- 一键呼叫：紧急情况下主动联系老人

F4：AI健康问答（RAG）（P1）

用户故事：

作为一位患有糖尿病的老人，我希望能用方言问AI"我能吃什么"，这样我不需要打字，也不用担心说普通话不标准。

功能描述：
- 老人用自然语言（支持普通话/方言）提问健康相关问题
- AI基于RAG知识库检索权威资料后回答
- 回答附带免责声明（非医疗诊断）
- 医疗关键词触发就医引导

知识库来源：
| 类别 | 数据来源 | 更新频率 |
|------|----------|----------|
| 药品说明书 | 国家药监局公开数据 | 季度更新 |
| 慢病管理指南 | 中华医学会发布 | 年度更新 |
| 饮食禁忌 | 权威营养学资料 | 半年更新 |
| 养老政策 | 民政部/卫健委文件 | 实时跟踪 |
| 长护险政策 | 各地医保局文件 | 按地区配置 |

AI能力需求：
- RAG检索增强生成（向量数据库 + 大模型）
- 医疗安全护栏（关键词检测 + 免责声明强制注入）

4.4 Agent 架构设计（Planner-Executor 模式）

结论先行：银发管家采用 Planner-Executor + 子任务模块化 混合架构。主 Agent 负责理解老人自然语言意图并规划任务链，多个子 Agent 按专业领域执行，结果由主 Agent 汇总后以适老化语言反馈。

4.4.1 为什么选 Planner-Executor（而非单体单循环 / 单纯多智能体编排）

对照 2026 年 7 月 AI Agent 主流四种架构：

架构模式 是否适合银发管家 判断理由
单体单循环（smolagents 类） ❌ 老人诉求常横跨"用药+血压+情绪+子女通知"多域，单循环处理易出现漏项、状态丢失
模块化工作流（LangGraph / ADK） 🟡 部分采用 用药提醒、血压录入等强规则+审批链场景适合，作为子 Agent 内部实现
Planner-Executor（Magentic-One） ✅ 主架构 银发管家是长程任务 + 复杂对话理解场景，需要拆解意图 → 分派 → 汇总，天然匹配
多智能体编排（CrewAI） 🟡 局部采用 仅在"社交陪伴"这种需要多角色协作对话的场景启用

核心权衡：老人不会说"帮我调用用药提醒 Agent"，只会说"我今天头晕，是不是降压药吃多了"。这需要主 Agent 具备意图理解 + 任务规划能力，把一句自然语言拆成 { 血压数据检索 → 用药记录检索 → 冲突检测 → 风险话术生成 → 是否通知子女判断 } 五步任务链——这正是 Planner-Executor 的核心能力。

4.4.2 Agent 分工与协议

    │用药 Agent│  │健康监测 │  │紧急响应│  │社交陪伴 Agent│
    │(模块化   │  │Agent    │  │Agent   │  │(多智能体编排)│
    │工作流)   │  │(工作流) │  │(工作流)│  │             │
    ├─────────┤  ├─────────┤  ├────────┤  ├─────────────┤
    │冲突检测  │  │血压趋势 │  │风险话术│  │情绪识别      │
    │提醒调度  │  │异常预警 │  │子女通知│  │话题生成      │
    │Qwen-Turbo│  │Qwen-Max │  │Qwen-Max│  │Claude-Fable-5│
    └─────────┘  └─────────┘  └────────┘  └─────────────┘

协议选型：
- MCP（Model Context Protocol）：主 Agent 与外部工具（手环 API、血压仪 SDK、微信通知）的标准化接口，避免每次接入都重写胶水层
- A2A（Agent-to-Agent）：主 Agent 与子 Agent 之间的通信协议，支持并行调度（如同时查用药+查血压）和结果聚合
- Skills：每个子 Agent 封装为独立 Skill 包，可复用、可版本化、可 A/B 测试

4.4.3 典型任务链示例

场景：老人说"我今天头晕，是不是降压药吃多了？"

1. [主 Agent · Planner] 意图识别：健康咨询 + 用药风险
   任务分解：
   ├─ Task-A: 查询今日血压记录（→ 健康监测 Agent）
   ├─ Task-B: 查询今日用药记录（→ 用药 Agent）
   ├─ Task-C: 药物-症状相关性分析（→ 用药 Agent · RAG）
   └─ Task-D: 情绪状态检测（→ 社交陪伴 Agent，静默运行）

2. [子 Agent 并行执行] · A2A 协议
   ├─ 健康监测 Agent 返回：今晨血压 145/95（正常范围偏高）
   ├─ 用药 Agent 返回：今晨已服氨氯地平 5mg
   ├─ 用药 Agent · RAG 返回：氨氯地平常见副作用含头晕（首周高发）
   └─ 社交陪伴 Agent 返回：情绪平静，无异常

3. [主 Agent · Executor] 结果汇总 + 适老化输出
   ├─ 判断：低风险，无需通知子女
   ├─ 生成回复："您今天血压145/95偏高一点点，头晕可能是氨氯地平的
   │            常见反应，一般一周内会缓解。建议今天多喝水、少走动，
   │            如果傍晚还头晕，我提醒您女儿好吗？"
   └─ 埋点：本轮对话进入随访队列，24h 后主动关怀

4. [审批边界] 涉及紧急/敏感场景时
   └─ 若血压>180 或提及自杀意念 → 强制走"紧急响应 Agent"
     → 触发子女推送 + 建议就医 + 记录日志（不可跳过）

4.4.4 面试可讲价值（AI PM 视角）

  • 技术判断力：不是所有 Agent 都要多智能体，Planner-Executor 是长程复杂任务的最优解，简单场景（如"设个提醒"）单循环即可，避免过度设计
  • 成本意识：主 Agent 用 GLM-5.2（Function-call 强），子 Agent 按任务专精选轻量模型（Qwen-Turbo 处理规则类），单老人月成本 ≤¥3
  • 合规边界：紧急响应走"审批链"而非 AI 自主决策——医疗健康场景，AI Agent 的自主权必须有护栏，这是 2026 年 AI PM 的核心素养
  • 可演进性：MCP + A2A 是行业标准协议，未来接入新工具/新子 Agent 无需重构主架构

八、风险评估与应对

8.1 风险矩阵

风险 概率 影响 等级 应对策略
老人不愿用小程序 中 高 🔴 子女端推动，先让子女注册后邀请老人
方言识别不准确 高 中 🟠 MVP阶段先用普通话，逐步接入方言
AI回答医疗合规风险 中 高 🔴 严格免责声明 + RAG知识库限定范围 + 人工抽检
获客成本过高 低 高 🟡 利用泰康代理人渠道，CAC控制在¥50以内
数据隐私合规风险 中 高 🔴 遵循PIPL要求，健康数据加密存储，用户单独同意
子女付费意愿低 中 中 🟡 免费试用期+明确价值主张（安心=值得付费）

8.2 合规要求

法规 要求 应对措施
《个人信息保护法》(PIPL) 健康数据属于敏感个人信息，需单独同意 用户注册时明确授权，可撤回
《互联网诊疗管理办法》 AI不得进行疾病诊断 功能定位为"健康咨询"，严格免责声明
《数据安全法》 健康数据跨境传输限制 数据存储在国内服务器
医疗器械监管 健康设备需认证 本项目不涉及硬件设备，无需认证
